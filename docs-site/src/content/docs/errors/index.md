## Read the contract for the failing surface

| Surface | Presentation | Recovery |
|---|---|---|
| Gateway HTTP | HTTP status and structured envelope; fields depend on the operation | Preserve operation/idempotency identity; follow supplied next actions and retry safety |
| CLI | JSON result/error and process exit status | Read stderr and complete JSON; pending verification is not verified deployment |
| SDK | Typed errors and type guards | Narrow with exported guards; fields differ by error kind |
| MCP | Tool result/error content | Inspect structured content and the tool schema; it is not a CLI process |
| Application runtime/Core | Runtime-specific diagnostic or typed exception | Consult the owning runtime and request context |

No universal envelope promises `status`, `suggestedFix` or `docs` on every error. See [CLI errors](/cli/errors/), [SDK types](/sdk/errors/) and [MCP recovery](/mcp/lifecycle/).

For deployment failures inspect `run402 doctor --project prj_example` and the returned operation's next actions. Do not repeat an ambiguous mutation or a paid request with a new idempotency key. Unknown future codes remain data; preserve their original details.

## Code destinations

The catalog records owning source locations and pinned external contributions. A listed code is addressable, not a promise that every interface emits it.
